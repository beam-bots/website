## A Late Command Is Still a Command

The main framework change since the
[October update](@/blog/progress-2026-10-12.md) is
[`bb` 0.33.0](https://github.com/beam-bots/bb/releases/tag/v0.33.0).

Previously, when an actuator was missing or took too long to answer a synchronous
command, the call exited. Now those cases return structured errors:

- **`ActuatorNotRunning`** means nothing received the command.
- **`CommandPending`** means the caller stopped waiting, but the command is still
  queued and will most likely be applied.

That distinction matters when the thing on the other end is a robot. A timeout isn't
a cancellation, and retrying can put another command behind the first one. The new
errors let a controller or UI handle these cases without catching exits. An actuator
that crashes while processing a command can still exit the caller.

**This is a breaking change:** code that relied on timeout or missing-process exits
needs to handle error tuples instead. Actuator paths are also validated now: pass a
bare actuator name or its full path from the root link. Partial paths raise an
`ArgumentError`, rather than half-working and publishing to the wrong topic.
The details are in [#293](https://github.com/beam-bots/bb/pull/293).

[`bb_mcp` 0.3.5](https://github.com/beam-bots/bb_mcp/releases/tag/v0.3.5) follows through
on that distinction: `send_joint_positions` reports a late actuator as `pending`, with
instructions to read joint state before sending another target. Telling an agent that
a move failed while the arm is busy doing it was not a recipe for good decisions.
[`bb_kino` 0.4.5](https://github.com/beam-bots/bb_kino/releases/tag/v0.4.5) displays the
new errors too. The equivalent
[LiveView change](https://github.com/beam-bots/bb_liveview/pull/173) is merged, but hasn't
had a new release yet.

## A Few Loose Ends Tied Up

**`bb` 0.32 is out.** The changes previewed last month shipped on 12 October in
[0.32.0](https://github.com/beam-bots/bb/releases/tag/v0.32.0): arm epochs, the unified
actuator delivery API, estimator freshness fixes and command-result validation. If
you're upgrading from 0.31, last month's migration notes still apply.
[`bb_ik_dls` 0.6.1](https://github.com/beam-bots/bb_ik_dls/releases/tag/v0.6.1) and
[`bb_ik_fabrik` 0.8.1](https://github.com/beam-bots/bb_ik_fabrik/releases/tag/v0.8.1)
update their trackers to use the new API.

**Setting a Feetech servo ID works again.** [Damir Batinović](https://github.com/Damirados) fixed the pattern matches
in `mix feetech.set_id`, which could crash on a perfectly successful `:ok` response.
That's in [`feetech` 0.4.1](https://github.com/beam-bots/feetech/releases/tag/v0.4.1).
Thanks, Damir!

**Policy actuator targets got a fix on `main`.** `bb_policy` was wrapping bare actuator
names in lists, turning them into partial paths. That lost messages from the proper
PubSub topic before, and raises under 0.33's stricter validation. It now
[passes targets through unchanged](https://github.com/beam-bots/bb_policy/pull/52).
There's no new GitHub release to announce for this one.

**Tests are doing less sleeping.** A sweep across core and the satellites replaced
many sleeps and timing guesses with messages, monitors and explicit synchronisation.
The [core PR](https://github.com/beam-bots/bb/pull/295) has the details. Waiting for
evidence that something happened makes for a much more useful test than hoping the CI
runner got round to it in 50 milliseconds.
